микросервис трекинга статуса тендеров.

| Задание | Каталог | Что внутри |

## Требования к окружению

PostgreSQL 16 — для обоих заданий. Python 3.12 — только для задания 6.

## Задание 4: схема БД

Проверяется без запуска приложения, тремя командами:

```bash
createdb -U postgres tender_registry
psql -U postgres -d tender_registry -v ON_ERROR_STOP=1 -f task-04-schema/01_schema.sql
psql -U postgres -d tender_registry -v ON_ERROR_STOP=1 -f task-04-schema/02_seed.sql
```

Затем любой файл из `task-04-schema/queries/`. Ожидаемые результаты запросов
приведены в [README задания](task-04-schema/README.md).

## Задание 6: микросервис трекинга статусов

```bash
cd task-06-service
createdb -U postgres tender_tracker
psql -U postgres -d tender_tracker -v ON_ERROR_STOP=1 -f schema/01_schema.sql
cp .env.example .env
poetry install
poetry run uvicorn app.main:app
```

Запросы удобно проверять через `http://127.0.0.1:8000/docs`. Установка без
Poetry, запуск тестов и описание эндпоинтов — в
[README задания](task-06-service/README.md).

## Независимость заданий

У каждого задания своя база данных и своя схема. Задание 4 не знает о
существовании задания 6, задание 6 не требует схемы задания 4 — поэтому
таблица `tenders` встречается в репозитории дважды, в разных базах и в разной
форме.

Это решение, а не рассогласование. Тендер в задании 4 обязательно ссылается на
заказчика закупки, и сервис из задания 6 не смог бы создать тендер одним
запросом: сначала потребовалась бы компания. Причины подробнее — в
[README задания 6](task-06-service/README.md).
